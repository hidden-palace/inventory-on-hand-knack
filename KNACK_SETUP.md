# Inventory On-Hand screen - verified Knack setup

The application is connected to the live Knack app with supported view-based requests. The private API key is not present in any frontend file, and the application contains no bundled demo or fallback inventory records. If Knack is unavailable or rejects a lookup, the page shows an error instead of substituting sample data.

## Verified data sources

| Purpose | Knack source |
|---|---|
| Inventory item header | Price List (`object_26`), `scene_463` / `view_1003` |
| Reorder-point detail | Price List Details, `scene_464` / `view_1004` |
| Inventory ledger | Inventory Transactions (`object_29`), `scene_470` / `view_1008` |

Items can be found using Supplier SKU (`field_724`) or OR SKU (`field_725`). Transactions are matched using OR SKU (`field_761`), with Item Code (`field_753`) displayed in the history grid.

## Inventory calculations

The screen derives balances from the immutable transaction ledger:

- Receiving Transaction: add Quantity to Destination Location.
- Inventory Transfer: subtract Quantity from Source Location and add it to Destination Location. Total inventory does not change.
- Order Usage, Damage, and Waste: subtract the absolute Quantity from Source Location.
- Cycle Count and manual adjustments: apply the signed Quantity to the location.
- Beginning Inventory and Customer Return, when added as types, are treated as inventory coming in.

Transactions are ordered chronologically to calculate the running balance. The current live Knack records calculate to 91 units for the configured default item: 45 Palmdale, 11 Santa Monica, and 35 Sherman Oaks.

These seven records are live database records. Their intentional test wording in the Notes field is preserved exactly as entered in Knack and is not generated by the page.

## Available inventory limitation

Current Price List and Inventory Transaction records do not contain a reserved-quantity or pending-transaction status. Consequently, the screen correctly reports Available equal to On Hand for the current data model.

If the business later reserves raw inventory before an Order Usage transaction is posted, add a reservation ledger/table or a Price List connection on Line Item. Available can then become `On Hand - Reserved` without redesigning the UI.

## Security

- The frontend sends `X-Knack-REST-API-KEY: knack`, never the private API key.
- Cost presentation is limited to configured role names when running inside Knack.
- Knack page/view access and Data Access Control remain the security boundary.
- The private API key used during read-only discovery must remain server-side and should be rotated after development.

## Files

- `index.html` - responsive page markup
- `inventory.css` - desktop and mobile styling
- `inventory-app.js` - lookup, calculations, alerts, filters, running balances, and scanner workflow
- `knack-config.js` - verified application, view, and field mappings
- `KNACK_DISCOVERY.md` - API discovery record without credentials

The current files can run as an external page or be hosted and embedded into Knack. For a direct Knack deployment, mount the HTML on the intended page and load the CSS/JavaScript from an approved HTTPS host or the Knack custom-code area.
